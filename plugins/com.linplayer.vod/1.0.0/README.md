# VOD 资源站

把一个影视资源站的**采集接口**接进来，像浏览网盘一样浏览它：分类树、海报墙、
剧集分集、多线路、搜索、点开就播。

**添加服务器 → 插件源 → VOD 资源站**，填接口地址就行，形如：

```
https://某个站/api.php/provide/vod/
```

> 插件不内置任何站点清单，地址得你自己填。

## 一个站 = 一个服务器

想用多个资源站，就在「服务器 › 添加」里加多条，每个站一条，在服务器页之间切换。

这不是偷懒，是插件沙箱的规则：manifest 里的出网白名单只写了 `$sourceServer`，
它在运行时展开成**你自己填的那个地址的 origin**。放行谁由你决定，不由插件决定 ——
插件想在一个实例里去打另外三十个域名，白名单会拦下来，这是对的。

## 目录长什么样

```
根目录
├── 📁 电影 / 连续剧 / 综艺 / 动漫 …      ← 分类树（两级）
├── 🎬 某某电影 · HD · 2026               ← 单集的直接点播
├── 📁 某某剧 · 更新至17集 · 2026          ← 多集的进去选集
└── 📁 下一页 ›（第 2 / 3393 页）
```

分类目录和本级内容是**混排**的：有的站顶级分类自己是空的（内容只挂在叶子分类上），
有的站又确实有。混排两种站都对，也少一条代码路径。

条目名里那串 ` · ` 是备注和年份 —— 宿主的条目只有一个 `name` 字段，信息只能挂在它上面。

## 五个实测出来的坑

**有的线路给的是网页播放页,不是流。** 同一部片挂两条线路,一条 `/share/<hash>`(GET
回来是 `<!doctype html>`)、另一条才是真 `.m3u8` —— 并排列出来的话用户有一半概率点到
黑屏。所以同一部片里**只要有一条线路的地址带媒体扩展名,不带的那些就不摆出来**;
一条都认不出时(无扩展名的直链确实存在)一条都不丢。

**有的站的分类树是残的。** `class` 里只有 `type_id` 和 `type_name`、**没有
`type_pid`** 的站是存在的。那种站上「电影 / 连续剧 / 综艺」这类父分类点进去是空的
(内容全挂在「动作片」这类叶子上),而父子关系站点根本没告诉我们,猜不出来。
这是站点的数据就长这样,不是插件漏了什么。

**列表接口没有海报。** `ac=list` 每条只回 8 个字段，没有 `vod_pic`，也没有
`vod_play_url`。拿它当列表就得「列 20 条 → 再打 20 次详情」。而 `ac=detail` 同样吃
`t` 和 `pg`，一次给回 20 条 × 83 字段，海报和播放地址全在里面。所以这个插件**从不调
`ac=list`**，测试里有一条断言钉着这件事。

**搜索只能用 `ac=detail&wd=`。** `ac=list&wd=` 会**返回全站内容**——看起来像搜到了
一大堆，其实一条都没匹配。这个坑很安静。

**必须自己带 User-Agent。** 宿主的 http 客户端默认一个头都不发，挂了 CF 的站会直接
403，而报错看起来像鉴权失败。

## 出网范围

插件自己只访问你填的那个接口地址。海报由界面直接加载、m3u8 由播放器直接取流，
两者都不经过插件，也就不受白名单约束 —— 插件只负责把地址交出去。

## 测试

```
node tools/test_vod.mjs
```

15 条用例,覆盖分类混排、翻页边界、多线路 `$$$` 对齐、网页播放页线路的取舍、脏数据过滤、
搜索关键词里带 `|`、以及「站点返回错误页」和「JSON 被截断」两种真实故障要报成两句不同的话。

夹具是从真实站点录下来的响应,只把主机名换成了 `example.com` —— 分隔符、字段名、字段
类型(`limit` 是字符串 `"20"`)、空值形态逐字保留,因为被测的正是这些。

这套用例是**逐条注入真 bug 验过会红的**(改成 `ac=list`、去掉 `isVideo`、`$$$` 写成
`$$`、翻页边界改成 `<=`、不过滤网页播放页 …… 每一条都让它变红过)。只会说 OK 的测试
和没有测试是一回事。
